# Архитектура NodeTaskEdit

## Обзор

NodeTaskEdit — это парсер бинарных файлов квестов Perfect World (`tasks.data`). Проект разбирает бинарный формат на JavaScript, позволяя читать и редактировать квесты через веб-интерфейс.

## Структура проекта

```
NodeTaskEdit/
├── lib/                          # Библиотека парсеров
│   ├── TaskFile.js              # Основной класс для загрузки файла

│   │
│   ├── core/                    # Основные парсеры
│   │   ├── LoadBinary.js       # Загрузчик задачи (точка входа)

│   │   ├── DescriptionParser.js # Парсер описания квеста
```

## Модули

### Точка входа: `TaskFile.js`

**Назначение**: Основной класс для работы с файлом `tasks.data`.

**Основные методы**:
- `load(filePath)` — загружает файл, читает заголовок и таблицу оффсетов
- `loadQuest(data, index)` — загружает конкретный квест по индексу

**Формат заголовка**:
```
+0x00: timestamp (int32)
+0x04: version (int32)    // 105, 108, 111, 118
+0x08: count (int32)      // количество квестов
+0x0C: offsets[count]     // таблица смещений (int32 каждый)
```

---

### Поток данных: `TaskStream.js`

**Назначение**: Обёртка над `Buffer` с методами для чтения бинарных данных.

**Основные методы**:
- `readInt32()`, `readUInt32()`, `readFloat()`, `readUInt8()` — базовое чтение
- `readWideString(lengthInChars)` — чтение UTF-16LE строк
- **`readTaskChar(length, key)`** — чтение XOR-зашифрованных строк (ключ = ID квеста)
- `seek(offset)` — позиционирование потока
- `getPosition()` — текущая позиция

**Особенность**: Названия квестов **зашифрованы XOR** с ID квеста в качестве ключа.

---

### Core: Основные парсеры

#### `core/LoadBinary.js`

**Точка входа** для парсинга одного квеста.

**Процесс загрузки**:
1. Читает фиксированную структуру (`FixedDataParser`)
2. Читает описание (`DescriptionParser`)
3. Читает трибут (`TributeParser`)
4. Читает 5 типов диалогов (`TalkParser`)
5. Рекурсивно загружает подзадачи

#### `core/FixedDataParser.js`

**Парсит структуру `ATaskTemplFixedData`** размером **0x420 байт** (1056 байт).

**Читает**:
- **Фиксированную часть** (1056 байт): ID, название, тип, лимиты, счётчики
- **Динамическую часть**: 
  - Временные таблицы (`TaskTm[]`)
  - Массивы регионов
  - Требуемые предметы/монстры/игроки
  - Награды (через `awards/*`)

**Использует**:
- `TaskStructs` для чтения базовых структур времени/координат
- `QuestStructs` для чтения структур квестов

#### `core/DescriptionParser.js`

Парсит текстовое описание квеста (зашифровано через ID).

#### `core/TalkParser.js`

Парсит диалоги NPC (5 типов: получение, невыполнение, сдача предметов, выполнение, награда).

#### `core/TributeParser.js`

Парсит дополнительные атрибуты трибута.

### Awards: Парсеры наград

Награды имеют сложную иерархическую структуру:

```
AwardDataParser (главный)
├── AwardCandParser         # Массив кандидатов наград
│   └── ItemWanted[]
├── AwardMonstersParser     # Монстры для вызова
└── AwardPQRankingParser    # Рейтинг публичных квестов
```

**Специальные награды**:
- `AwardItemsScaleParser` — награды по шкале предметов
- `AwardRatioScaleParser` — награды по соотношению

### Structs: Вспомогательные структуры

#### `structs/TaskStructs.js`

**Базовые структуры** из IDA:

| Функция | Размер | Описание |
|---------|--------|----------|
| `readTaskTm()` | 24 байта | Структура времени (год, месяц, день, час, минута, день недели) |
| `readZoneVert()` | 12 байт | 3D координата (x, y, z) |
| `readTaskExpression()` | 8 байт | Выражение (тип, параметр) |
| `readMonstersContrib()` | 16 байт | Вклад монстров |
| `readRegionArray()` | 24 байта × N | Массив 3D регионов (min/max) |

#### `structs/QuestStructs.js`

**Структуры квестов** из IDA:

| Функция | Размер | Описание |
|---------|--------|----------|
| `readItemWanted()` | 17 байт | Требуемый предмет (ID, количество, вероятность) |
| `readTeamMemWanted()` | 36 байт | Требования к члену команды (уровень, раса, класс, пол) |
| `readMonsterWanted()` | 30 байт | Требуемый монстр для убийства |
| `readPlayerWanted()` | 37 байт | Требуемый игрок для PvP |

## Форматы данных

### XOR Шифрование

Названия квестов зашифрованы простым XOR:

```javascript
// Ключ шифрования = ID квеста (int16LE)
const key = Buffer.alloc(2);
key.writeInt16LE(questID, 0);

// Расшифровка
for (let i = 0; i < length; i++) {
    decrypted[i] = encrypted[i] ^ key[i % 2];
}
```

### Фиксированная структура (0x420 байт)

Основные оффсеты в `ATaskTemplFixedData`:

```
0x000: m_ID (uint32)                    // ID квеста
0x004: m_szName (wchar_t[30])          // Название (60 байт, XOR)
0x040: m_bHasSign (uint8)              // Флаг подписи
0x041: [указатель, пропустить 4 байта]
0x045: m_ulType (uint32)               // Тип квеста
0x049: m_ulTimeLimit (uint32)          // Лимит времени
0x069: m_ulTimetable (uint32)          // Счётчик временных таблиц
0x0A9: m_ulDelvRegionCnt (uint32)      // Регионы доставки
0x0E8: m_ulSuitableLevel (uint32)      // Подходящий уровень
...
0x420: [конец фиксированной части]
```

## API сервера

### `GET /api/quests`

Возвращает список всех квестов:

```json
{
  "total": 12529,
  "items": [
    {
      "id": 31389,
      "name": "Сертификат влюбленных",
      "hasSubtasks": false,
      "subtaskCount": 0
    },
    ...
  ]
}
```

*Примечание: Эндпоинт оптимизирован и возвращает только метаданные. Полная структура доступна по ID.*

### `GET /api/quests/:id`

Возвращает полные детали квеста. Поддерживает **рекурсивный поиск**: если запрошен ID подквеста, сервер найдет его внутри соответствующего дерева задач.

### `GET /api/quests/:id/subtasks`

Возвращает список непосредственных подзадач для указанного квеста.

```json
{
  "questId": 31389,
  "subtaskCount": 2,
  "subtasks": [
    { "id": 12345, "name": "Подквест 1", "hasSubtasks": true },
    { "id": 12346, "name": "Подквест 2", "hasSubtasks": false }
  ]
}
```

## Технические детали

### Поддерживаемые версии

- **Версия 118** (полная поддержка)
- Версии 55, 105, 108, 111 (частичная поддержка)

### Архитектурные решения

1. **Разделение по категориям**: Парсеры разделены на `core/`, `awards/`, `structs/` для лучшей организации
2. **Вынос структур**: Вспомогательные функции чтения вынесены в отдельные модули
3. **Ленивая загрузка**: Квесты загружаются по требованию через оффсеты
4. **Рекурсивная индексация**: Все подквесты индексируются при старте для быстрого доступа (O(1) lookup)
5. **Поэтапный парсинг**: Сначала фиксированная структура, затем динамические массивы

### Известные ограничения

- Поддержка только чтения (запись будет добавлена в будущем)
- Редактор пока не поддерживает сохранение изменений обратно в файл
